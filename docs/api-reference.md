# API Reference

This is a high-level reference to the route-handler surface present in the current application. The implementation in `app/api/**/route.ts` is authoritative for exact HTTP methods, payload fields, status codes, and authorization. This document intentionally avoids inventing request/response schemas.

## Route inventory

| Route | Area | Purpose |
|---|---|---|
| `/api/auth/login` | Authentication | Authenticate an application user |
| `/api/auth/logout` | Authentication | End the current application session |
| `/api/auth/me` | Authentication | Return the current authenticated user context |
| `/api/auth/signup` | Authentication | Public signup endpoint; registration is restricted by server-side role policy |
| `/api/auth/switch-camp` | Authentication | Switch the active camp context where permitted |
| `/api/admin/stats` | Administration | Read administrative summary statistics |
| `/api/camps` | Camps | Read and manage camp records according to role |
| `/api/complaints` | Complaints | Submit and manage complaint records |
| `/api/requests` | Requests | Create and list relief requests |
| `/api/requests/[id]` | Requests | Read or update a specific request |
| `/api/restock` | Inventory | Manage restock requests |
| `/api/stock` | Inventory | Read/update camp stock |
| `/api/volunteers` | Volunteers | Read and manage volunteer records |
| `/api/weather` | External evidence | Retrieve weather/rainfall information |

## Role model

The database user roles currently include:

- `admin`
- `camp_manager`
- `volunteer`

Authorization must be enforced server-side. Hiding a UI control is not authorization. Public request/status workflows should expose only the minimum information needed for the public task; administrative and camp-specific records require authenticated role checks.

## Live AI analysis

The five-agent analysis is currently orchestrated by the server-rendered request detail flow rather than exposed as a public standalone API endpoint.

- A camp manager opens `/queue/[id]`.
- The server checks the persisted analysis and its timestamp.
- A fresh cached result is reused for ten minutes.
- An explicit refresh requests a new analysis.
- Volunteer task views read the saved result; they do not trigger another model run.

See [AI agent runtime](ai-agent-runtime.md) for the data contract and safety constraints.

## Integration guidance

Before building an external client:

1. Inspect the matching `app/api/**/route.ts` file.
2. Confirm supported methods and validation rules.
3. Confirm authentication and role requirements.
4. Confirm whether the route returns persisted records or derived/external data.
5. Add contract tests before treating the endpoint as a stable public API.

No public OpenAPI/Swagger contract is currently generated by the project.
