# Hackathon MVP Planning

## Workflow
1. Restate the problem in one sentence and identify the primary user.
2. Define the single most valuable end-to-end user journey.
3. Separate must-have MVP requirements from stretch goals.
4. Write testable acceptance criteria for each MVP requirement.
5. Identify external services, credentials, data sources, and failure modes.
6. Design the smallest architecture that supports the journey.
7. Divide work into independent tasks with exclusive file ownership.
8. Define a demo script that exercises the real product, not slides alone.

## Guardrails
- Time-box exploration. Validate the riskiest assumption early.
- Prefer one complete workflow over many incomplete screens.
- Use mock/demo data only when clearly labeled and safe.
- Never hide failures behind fake success messages.
- Keep a list of known limitations for the final presentation.
